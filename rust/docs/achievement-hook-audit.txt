CREDIT SHAPE LEGEND
  abs   = report the character's current absolute value (state-like; high-water is the meaning)
  +N    = increment_matching(kind, N, |r| <match>) at a success-only event
  flag  = increment/abs 1 at a one-shot success event (complete_num 0, objective satisfied by >0)

=== LOCK / INTEGRATION RULES ===
* achievement_manager.rs::report_values (L102), increment_matching (L144), initial_snapshot
  (L215) internally take `server.systems.economy.ops_lock()` AND `player.data()`.
  ItemTxn::begin (economy/inventory.rs L67) takes the SAME ops_lock -> calling a report while
  an ItemTxn guard, the economy gate, a container lock or the character lock is held
  self-deadlocks. Always report after the locks are dropped.
* Existing callbacks that already run outside locks (preferred surfaces):
  - economy/fx.rs::flush (L40) item Acquired/Consumed (after ItemTxn guard release).
  - npcs/npc/death.rs::before_death -> NpcHooks::on_npc_killed per eligible player (no locks).
  - quests/events.rs public API: documented "must be called without the player data lock";
    nested calls from quest hooks are queued and run before the op ends (run_or_queue).
  - skills/combat.rs::character_death_tail: drop the `victim_p.data()` guard first.
  - cast/craft/loot/repair/specialty/enchant handlers: their ItemTxn blocks are explicit and
    end (or can be closed) before the report.
* Where the success data is born inside a lock/ItemTxn, use a bounded operation return:
  craft products+grades, loot granted list, repaired items list, auction sold (buyer/seller),
  check_wanted_threshold faction change. Additive alternative: a new no-op default hook
  method on the owning subsystem's hook trait, called at the same tail point.
* Entry path: AchievementContent::initial_snapshot is implemented but has NO caller yet (only
  manager tests). Wire it into world/session entry (see CSNotifyInGame in later C#) - this is
  the surface that must run before/with the list push and after the character lock is free.
